# Agent Session Context

## Context

A less technical user asked the agent to research a market, compute TAM, and analyze named competitors. The agent ran ~4 min, produced a deep report, and updated the brain. They loved the report, then said: "I'd rather just do this in chat. What's different than chat?"

This is not a speed complaint. It's a value attribution failure. ChatGPT trained the market to believe the unit of AI value is the message. We ship work. A 4-minute deep research run is a deliverable, but we presented it inside a chat container, so it got judged on chat-turn latency.

The fix isn't a second "chat tab" because that breaks the one-unified-co-founder thesis. The fix is to make the surface legibly communicate the work that's happening, and frame the output as a deliverable, not a slow reply.

Full thinking: `brain/wiki/product/chat-vs-agent-framing.md`.

## Goal

Ship a bundle of changes to the agent surface so a new user understands, viscerally, that deep agent runs produce deliverables, not slow messages. After this lands, the answer to "what's different than chat?" should be obvious without anyone having to explain it.

Ship this as one visible bundle, not five trickle improvements. The relaunch moment is part of the value.

## Scope: Five Changes, In Ship Order

### 0. Mode Announcement At Start Of Run

Smallest, highest expectation-setting impact.

Before any run expected to be >~20s, the agent posts an opening assistant message:

> This is a deep research run. ~5 min, I'll deliver X and save findings to your brain. Want me to also do Y?

Implementation: system prompt change plus light heuristic / classifier on the first turn to decide deep vs fast.

Pairs with item 4, richer turn vocabulary. This is an assistant turn before tool calls begin.

### 1. Artifact Rendering + Save-To-Brain

Biggest perception delta.

Deep run outputs no longer render as chat bubbles. They render as a named artifact card: title, short summary, "saved to brain: N facts" line, expand-to-full, one-click save / unsave.

This is the single change that operationalizes the whole reframe. If only one of the five ships today, it's this one.

Even a crude v1 is fine. The boxed component with title + summary + brain indicator is enough to shift perception.

### 2. Humanized Tool-Call Phrasing

Replace raw tool names like `exa_search` with a contextual one-liner generated by the model right before the call:

> Looking for 10 competitors in $market

Keep the raw tool name available on hover / expand for technical users. Translate, don't hide.

### 3. Streaming Gap Fix

Bug, not feature.

Today the stream goes silent during model "thinking" phases. The user reads silence as broken.

Minimum bar: no >2s window with nothing happening in the UI. A "thinking..." pulse is acceptable.

This is table stakes. Ship the fix, don't over-design it.

### 4. Step Collapse After Completion

Conductor-style.

During the run: steps expanded, because the labor is the value.

After completion: steps collapse to a one-line summary like "12 steps, 4 min" with click-to-expand. The artifact from item 1 is the headline.

Two states, two defaults.

### 5. Richer Turn Vocabulary In The Agent Loop

Architectural. Protect from rush.

Today the loop is roughly:

```text
user -> tool_call -> tool_result -> assistant_message
```

Extend it to support:

- Intermediate assistant utterances mid-run, including mode announcements, status, and clarifying questions.
- User steering messages on an in-flight run, such as "skip competitor Z, add W", without starting a new session.
- Mid-run assistant clarifications that block on user response.

Open design questions to resolve before code:

- How do interrupts work mechanically? Do we cancel in-flight tool calls, or queue the steer for the next loop iteration?
- Does a mid-run steer count as a turn for context / history?
- How does an assistant clarifying question compose with tool calls that are already pending?

This is the highest long-term value change in the bundle and the most likely to be regretted if rushed. Spend a couple of hours on the design doc before touching code.

## Recommended Ship Order

1. Mode announcement: small prompt change, sets expectations immediately.
2. Artifact rendering + save-to-brain: biggest perception delta.
3. Humanized tool-call phrasing: cheap, makes labor legible.
4. Streaming gap fix: bug fix, table stakes.
5. Step collapse after completion: small polish, pairs with item 1.
6. Richer turn vocabulary: design first, then build.

## Success Criteria

- A new user running a deep task, such as market research, does not ask "what's different than chat?" unprompted in their first session.
- The output of a deep run is perceived as a thing the agent made, not as a slow reply.
- At least one returning user references the brain growth, such as "it remembered X from last week", within 2 weeks of shipping.
- No >2s silent UI gap during any run.

## Out Of Scope

- A separate chat tab / chat-vs-agent toggle. Breaks the unified co-founder thesis. See framing doc for why.
- A new "fast model" product. The agent decides its own gear; the user doesn't pick.
- Marketing copy / landing changes. Those follow the surface change, not lead it.
