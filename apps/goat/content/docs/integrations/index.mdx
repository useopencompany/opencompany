## What integrations do

Integrations connect external systems to Goat so chat, tasks, and Brain ingestion can work from live company context. Some integrations expose tools to agents; others feed source items into the Brain ingestion queue.

## Current categories

- **Tool connectors** let Goat call a provider API on the user's behalf. Gmail, Google Calendar, Google Drive, GitHub, Linear MCP, Latitude MCP, PostHog MCP, and Slack use OAuth; Attio uses a workspace API key; Stripe uses a restricted, read-only workspace key. Main chat exposes curated actions across these connections. Gmail can save new plain-text drafts for manual review or send new plain-text emails, Drive can read Google Docs and Sheets, create new Docs with optional initial text, make exact Doc text replacements, and update or append Sheet values, Linear can create or update issues and add comments, Calendar can create events, and Attio can update records or existing list entries. PostHog can inspect dashboards and saved insights, run focused trends, funnel, retention, paths, stickiness, and lifecycle queries, and create a new insight on a chosen dashboard. Latitude exposes its live API-backed MCP catalog, so Goat automatically discovers newly available tools. Gmail draft creation defaults to On and never sends; communication and other external writes require confirmation by default. Stripe actions are read-only.
- **Brain source connectors** turn external activity into `goat.brain_source_items` and enqueue durable Brain ingestion. Jamie meeting notes, Granola meeting notes, Slack conversations, Linear issue activity, and chat captures use this shape.
- **Webhook connectors** receive provider deliveries at Goat API routes. Incoming payloads must authenticate at the route boundary before they can enqueue work.
- **API-key poll connectors** store a provider API key and let Goat poll for new activity when the provider offers no webhooks. Granola uses this shape.

## Where to configure

Personal OAuth integrations and workspace connections live under **Settings → Integrations**. Gmail reads and draft creation default to **On**, while sending defaults to **Ask**. Creating drafts and sending remain separate Goat permissions even though Google's `gmail.compose` OAuth grant covers both operations; existing Gmail connections must reconnect once to enable drafts when that grant is missing. Drive file discovery plus Google Doc and Sheet reads also default to **On**, while editing Google Docs or Sheets defaults to **Ask**. Drive accounts connected before Doc or Sheet editing was introduced must grant the added Google permissions once from this screen. Slack chat actions keep channels, direct messages, threads, search, and people under one **Read Slack** permission, which defaults to **On**. PostHog keeps product-data and query access under **Read analytics** (On) and saving a new insight under **Create insights** (Ask). Its hosted MCP connection is restricted to the dashboard, insight, query, event-definition, and property-definition OAuth scopes Goat actually uses. Latitude tools marked read-only by its MCP server default to **On**; mutations and tools without a read-only annotation default to **Ask**. See [PostHog's MCP guide](https://posthog.com/docs/model-context-protocol) and [Latitude's MCP guide](https://docs.latitude.so/getting-started/mcp) for the provider-side connection contracts. Brain source routing lives on each brain's settings page under Sources. Stripe is workspace-owned and can only be connected or rotated by a workspace admin.
