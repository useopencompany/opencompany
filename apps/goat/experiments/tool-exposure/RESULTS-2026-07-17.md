# Tiered Tool Exposure: Spike Results

Date: 2026-07-17<br>
Model: `anthropic/claude-sonnet-5` through Vercel AI Gateway<br>
Main sample: 15 paired tasks, one run per mode<br>
Scale sample: three paired tasks at 20, 60, 100, 160, 240, 400, and 800 tools

## Decision

Do not put the fixed-curation version into Goat's main chat layer yet.

The tiered design clearly wins on context size, but it did not preserve flat exposure's selection
quality on the hardest multi-integration task and it added model-step latency for non-curated
operations. The useful follow-up is a hybrid: keep deterministic integration routing and lossless
pointers, but make Level-1 tool candidates message-specific using deterministic lexical/embedding
retrieval rather than a static four-tool list.

This is a negative result for the exact prototype, not for deterministic tiering in general.

## Main results

All numbers below are computed from provider-reported usage and recorded tool calls.

| Metric | Tiered | Flat | Difference |
| --- | ---: | ---: | ---: |
| First model-step input tokens | 1,739 | 21,985 | -92.1% |
| Cumulative input tokens per user turn | 7,033 | 56,264 | -87.5% |
| Required-tool recall | 97.3% | 100.0% | -2.7 pp |
| Tool precision | 90.1% | 96.1% | -6.0 pp |
| Strict exact success | 73.3% | 86.7% | -13.4 pp |
| Mean model steps | 3.13 | 2.53 | +23.7% |
| Mean wall latency | 11.40 s | 9.08 s | +25.5% |
| Provider errors | 0/15 | 0/15 | — |

The static serializer estimate was 974 initial tokens tiered versus 13,493 flat (-92.8%). Actual
provider input was higher because it includes provider wrappers, the system/user messages, and the
provider's tokenizer, but the relative reduction was close.

Strict exactness intentionally penalizes reasonable prerequisite reads. For example, both modes
fetched a CRM record after searching it, although the benchmark only required search and update.
Required-tool recall is the closer proxy for task completion; precision and exactness expose extra
or redundant selection behavior.

## Failure and recovery behavior

The deterministic trigger expanded 22 of 23 required integration occurrences (95.7%). Its one
deliberate false negative was the implicit request to broadcast to “our company chat destination,”
which avoided every Slack keyword. The model recovered: it followed `integration://slack`, listed
channels, and sent the message. Task-level false negatives were therefore 1/15 and recovery was 1/1.

Across 10,000 trigger runs against a 40-integration registry, keyword matching took 0.0106 ms mean
and 0.0176 ms p95. The trigger itself added no meaningful latency. Tiered latency came from extra
model steps:

- The model explicitly requested a complete Level-1 integration directory on 6/15 tasks.
- It explicitly requested Level-2 schemas on 1/15 tasks (two schemas in the five-source digest).
- The engine resolved Level 2 at actual call time 29 times.

All five single-integration non-curated tools succeeded after a Level-1 directory expansion without
an explicit Level-2 request. That validates the lossless path, but their latency was roughly double
flat mode because discovery added a model step.

The material miss was the five-source digest. The prompt explicitly asked to list Linear issues and
GitHub pull requests. Static Level 1 only showed `search_issues`, so the model expanded and called
those nearby curated tools instead of discovering `list_issues` and `list_pull_requests`. Tiered
recall on that task was 3/5; flat recall was 5/5. This is an anchoring failure caused by the curated
view, not a trigger miss.

## Scaling and the ceiling question

The table uses the same three Linear tasks at every size. Integration counts above five contain
synthetic distractor clones, so this is a stress probe rather than a realistic integration mix.

| Integrations | Tools | Flat first-step tokens | Flat recall | Flat precision | Tiered first-step tokens | Tiered recall | Tiered precision |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 20 | 4,437 | 100% | 100% | 1,480 | 66.7% | 50.0% |
| 3 | 60 | 12,685 | 100% | 83.3% | 1,569 | 66.7% | 66.7% |
| 5 | 100 | 21,977 | 100% | 83.3% | 1,661 | 66.7% | 50.0% |
| 8 | 160 | 34,581 | 100% | 61.1% | 1,891 | 66.7% | 50.0% |
| 12 | 240 | 52,470 | 100% | 83.3% | 2,202 | 66.7% | 50.0% |
| 20 | 400 | 88,505 | 100% | 83.3% | 2,825 | 66.7% | 50.0% |
| 40 | 800 | 177,209 | 100% | 100% | 4,377 | 66.7% | 50.0% |

No flat required-recall ceiling was found through 800 tools. Precision first degraded at 60 tools,
bottomed at 61.1% at 160 tools, and then recovered non-monotonically. At 160, one run called a tool
from a synthetic Linear clone as well as the correct base tool—the clearest distraction failure—but
the required call still happened. With only three single-shot tasks per size, that is a signal to
investigate, not a reliable threshold.

Tiered recall held constant at 66.7%, but for the wrong reason: the same `list_issues` →
`search_issues` curated-view miss occurred at every scale, including one integration. Tool count was
not its limiting factor.

The defensible ceiling result is therefore a lower bound: Sonnet 5 still achieved 100% required-tool
recall with 800 flat mock schemas, at the impractical cost of 177k input tokens on the first step.
The experiment does not support an industry-style claim that selection collapses around five to
seven integrations.

## Recommendation for a follow-up

Build a second spike before touching Goat production:

1. Keep Level-0 integration summaries, stable pointers, generic dispatch, call-time validation, and
   deterministic trigger logging.
2. Replace static Level-1 curation with deterministic per-message tool retrieval inside each matched
   integration. Lexical aliases plus an embedding threshold can still avoid an LLM routing call.
3. Always include a compact “other operations available” directory signal so a nearby curated tool
   does not look exhaustive.
4. Run at least five repetitions across Goat's supported model set and use real MCP `listTools`
   schemas. Score argument semantics and final task state, not only tool identity.
5. Compare total cost and latency with provider caching enabled; tiered's extra steps matter as much
   as its input-token savings.

## Reproducibility and limits

Raw run artifacts are in the workspace at:

- `apps/goat/.context/tool-exposure-full.json`
- `apps/goat/.context/tool-exposure-extended-scale.json`
- `apps/goat/.context/tool-exposure-static.json`

The live result is a small, single-model, single-repetition spike. Mock tools remove integration
network latency and external failures. Scaling uses repeated distractor catalogs. Model generation
is not seeded. The results are sufficient to reject the fixed-curation design for immediate
production use, but not to estimate production success rates.
