---
title: Tasks
description: Delegate a job, follow its progress, and continue from its result.
---

A Task is a job with a request, status, activity history, and result. Use it when you want work to
continue in the background and have a clear place to return to.

Enable **Tasks & Workflows** under **Settings → Preferences → Beta features** first.

## Start a Task

From Home or a built-in opencompany Chat, type `#task` in the composer and describe the job:

```text
#task Review the open pull requests in OWNER/REPO.
Identify any missing test evidence or unresolved review comments.
Return a short report with a link to each PR and its next action.
```

This example needs a connected GitHub Plugin with the relevant read tools available. Replace
`OWNER/REPO` with your repository. A [Workflow](/docs/core-concepts/workflows-and-schedules) or
schedule also creates a Task each time it runs.

Specify the deliverable and what counts as done. If a decision is required, say what the agent
should prepare before asking you to decide. Background work cannot rely on live tool approvals;
see [Permissions](/docs/core-concepts/integrations#background-and-coding-work).

Starting a `#task` currently doesn't support attachments. Put the required context in the request
or identify an accessible source. You can attach files to follow-ups in the Task's conversation.

## Follow progress

Open **Tasks** to browse the board or list. Filter by Workflow or time range to find the relevant
run. Open a Task to see its **Activity**, status, result, and recorded cost. **View run** opens the
execution conversation.

| State | What to do |
| --- | --- |
| Queued or running | Follow the activity or open the run to see current work. |
| Waiting for you | Read the question or proposed result and reply with the missing input. |
| Done | Review the result and any remaining items marked as needing attention. |
| Failed | Read the error, resolve its cause, and provide a follow-up when ready. |
| Canceled | Inspect what finished before cancellation before deciding to continue. |

A completed run can still report that the outcome needs attention. Read the result before treating
the underlying job as finished.

## Continue the same job

Leave a comment on the Task or send a message in its conversation. The follow-up continues the
same job and history. For example:

```text
The missing test run is now linked on PR 42. Recheck that PR and update the report.
```

Use the active run's cancel control when you want execution to stop. Canceling doesn't undo actions
that already completed in a connected service.

## Archive a Task

You can archive a Task once its run has settled, including a Task **Waiting for you**, a completed
Task, or one that failed or was canceled. Archiving preserves its history and outcome, including
any outstanding question. It doesn't resume work. Queued or running Tasks must settle before they
can be archived.

Use Chat for work you want to steer turn by turn. When the same Task keeps coming up, turn its
process into a [Workflow](/docs/core-concepts/workflows-and-schedules).
