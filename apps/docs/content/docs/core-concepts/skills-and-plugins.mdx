title: Skills
description: Teach the agent a reusable method and invoke it with a slash command.

A Skill is a reusable set of instructions for a particular kind of work. Use one for your team's
review method, document format, research process, or coding conventions. Skills can be used in Chat
and selected for Workflow steps.

A Skill teaches the method. A [Plugin](/docs/core-concepts/plugins) can package Skills together with
tools or events. A [Workflow](/docs/core-concepts/workflows-and-schedules) defines the job's steps and
trigger.

## Use a Skill

Type `/` in Chat and choose an enabled Skill. Add the specific request after its command:

```text
/release-review Review the release in OWNER/REPO from v1.2.0 to v1.3.0.
Return the checks that passed, missing evidence, and open questions.
```

This example assumes you've created a Skill named `release-review`. The command comes from the
Skill name. A Skill that requires a connected service still needs that service's Plugin, account,
and permissions.

## Create your own

Workspace admins can create Skills in **Settings → Skills → New skill**. Enter a name, a
description of when it applies, and the instructions.

For a release-review Skill:

- **Name:** `release-review`
- **When to use this skill:** Review a proposed software release for test evidence and unresolved risks.
- **Instructions:** Use the example below, then adapt it to your team's process.

```markdown
Read the release scope and linked pull requests before writing the review.
Use the repository's existing release checklist when available.
For each check, record its evidence and whether it passed, failed, or needs verification.
Link to the original source for each finding.
Return a concise recommendation followed by open questions.
Ask for missing release identifiers rather than guessing them.
```

Keep reusable instructions in the Skill and put each job's repository, date range, and deliverable
in the prompt. Describe observable results, such as linked evidence, instead of broad requests to
“be thorough.”

## Create a Skill from successful work

In the same Chat, ask:

```text
Turn the release-review process we just used into a workspace Skill.
Keep the method reusable and leave this release's names and dates out of the instructions.
```

This creates a Skill immediately when you're a workspace admin. It works in built-in Chat, Codex,
and Claude Code. Open **Settings → Skills** to review the saved instructions.

Ask the agent to update a named workspace-authored Skill to refine it, or open it in Settings.
Use **Save changes** or Command/Ctrl+S to save, and **Discard changes** to return to the saved text.
If another person or agent edited the Skill, reload its latest version before reapplying your edit.

## Import a Skill

Choose **Import skill** in **Settings → Skills**, paste a supported public GitHub or skills.sh URL,
and review the preview. Check the selected Skill, instructions, bundled files, and resolved version
before importing.

Imports use the standard Agent Skills format with a `SKILL.md` file. The name and description are
frontmatter; the body contains the instructions. Workspace authoring generates this structure for
you. A separate `command` frontmatter field isn't supported.

Imported and Plugin Skills cannot be rewritten through the workspace Skill editor or Chat editing
tools. Update their source and replace the installed bundle, or author a separate workspace Skill.

## Versions, disabling, and archiving

A saved or imported Skill is an immutable bundle. Editing a workspace Skill creates a new bundle.
Existing Chats and Tasks keep the versions they already captured, so a new edit doesn't silently
change work in progress. Start a new Chat to verify a revised Skill.

**Disable** prevents the Skill from being selected for new work. **Archive** removes its active
installation. Neither action rewrites previous results.

Editing a Skill file inside a coding sandbox changes that local snapshot only. Use Settings or ask
Chat to update the workspace Skill when you want the change shared.
