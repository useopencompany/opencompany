## Agent Skills

Workspace admins manage Agent Skills in **Settings → Skills**. Choose **New skill** to author one
for the workspace, or preview a supported public GitHub or skills.sh URL before importing it.
Workspace-authored Skills use the same official Agent Skills document format as imported Skills;
opencompany generates the `SKILL.md` frontmatter from the name and description and stores the
instructions as its Markdown body. The slash command is always derived from the Skill name as
`/<skill-name>` rather than stored in a separate `command` field.

Workspace admins can also create one from a successful Chat. Explicitly ask Chat to “turn this
into a Skill”; Chat synthesizes the reusable method from the conversation and immediately creates
a standard workspace-authored Skill. This works in built-in Chat, Codex, and Claude Code sessions.
Ask to update a named Skill to revise it, or to remove it to archive its installation. Only workspace
admins can use these management tools, and imported or Plugin Skills cannot be edited this way.

Agents use `workspace_skills` to list installations (including disabled Skills), read the latest saved
instructions without activating them, or archive a named installation. `create_workspace_skill`
creates a new Skill; `edit_workspace_skill` updates an existing workspace-authored one. Before editing,
read the latest version and pass its `bundleId` as `expectedBundleId` to prevent overwriting another
edit. Files mounted in a coding sandbox and instructions activated in a Chat are versioned snapshots;
editing those local files does not update the workspace Skill.

Open a workspace-authored Skill in **Settings → Skills** to edit its Markdown instructions directly.
The short “When to use this skill” field describes when the agent should apply it. Choose **Save
changes** (or use Command/Ctrl+S) to save, or **Discard changes** to return to the saved text. Failed
saves preserve your draft, and saving checks that another user or agent has not changed the Skill
since you opened it.

Imported Skills are validated for official frontmatter, canonical bundle name and directory
alignment, every bundled file, and the resolved commit. A standalone Skill can be discovered in a
differently named repository directory because opencompany installs the canonical bundle under its
declared name and shows that normalization in the preview. Plugin Skill directory names remain part
of the Plugin package and must match. Unknown fields such as the retired `command` extension are
rejected.

Installed bundles are immutable. Editing a workspace-authored Skill or replacing an imported Skill
creates a new bundle and moves the workspace installation to it. A Skill cannot switch between
workspace-authored and imported provenance. Enable, disable, and archive control whether new Chats
and Tasks can select it. Existing Chats and Tasks retain the exact bundle IDs they already
captured. Type `/` in Chat and select a Skill to invoke it as `/<skill-name>`.

## Agent Plugins

Workspace admins manage Agent Plugins in **Settings → Plugins**. A Plugin install stores the exact
package, its valid immediate-child Skills, and an install report. An invalid Plugin manifest fails
the install; invalid child Skills are skipped and reported. Standalone Skills win name collisions,
then the alphabetically earlier Plugin name wins between Plugins. Settings shows hidden collisions.

Plugin Skills are passive instructions. Installing or enabling a Plugin does not automatically
connect an account. Remote HTTP and SSE MCP entries register with the server-side action gateway;
their URLs and credentials are not passed to Main Chat or coding sandboxes.

## MCP approval and Plugin data

An admin must approve the exact installed Plugin version before its stdio MCP servers can start.
Replacing the Plugin produces a new integrity and requires new approval. The approval UI shows the
command, arguments, and declared environment variable names, never secret values. Main Chat does
not start Plugin processes; approved MCP runs only in Codex and Claude coding sandboxes.

Each Plugin receives a writable `PLUGIN_DATA` directory. opencompany restores and checkpoints a
bounded workspace archive so data survives sandbox and Plugin replacement. Archiving a Plugin stops
its Skills and MCP from entering new turns but does not implicitly erase Plugin data.

## Historical Skills

The former Brain-backed Skill editor, custom command frontmatter extension, and legacy activation
replay have been removed. Workspace authoring now creates standard immutable Skill bundles instead
of restoring that legacy data model. Old Chat messages remain readable, but their historical Skill
activations are not executable and were not converted into new bundles.
