## Install and connect

1. Open **Plugins → Granola**.
2. Select **Install** and review the integrity-pinned package.
3. Select **Connect Granola account** and finish Granola's browser OAuth flow.

Granola uses Dynamic Client Registration, so you do not need to create an API key, client ID, or
client secret for MCP. The OAuth credential stays encrypted and server-side. The plugin gateway
sends it only to Granola's reviewed `https://mcp.granola.ai/mcp` endpoint.

Granola MCP follows the account's active workspace and the access allowed by your Granola plan and
workspace settings. Basic accounts can query only recent notes and do not receive every paid tool.
Enterprise workspaces may require an admin to enable personal or public note access before the
connection returns meeting data.

## Tools and permissions

The reviewed tools use two controls:

- **Check Granola account — On:** confirm the connected email and active Granola workspace.
- **Read meeting content — Ask:** search meetings or read folders, attendees, private notes,
  summaries, and paid-plan transcripts only after approval.

Any newly discovered or unclassified tool fails safe at **Ask**, even when the server marks it
read-only. Persistent coding sessions receive only tools set to **On**. You can change these modes
for your connection on the Granola plugin page.

Meeting titles, attendee identities, private notes, and verbatim transcripts can contain sensitive
customer or company information. Review the requested scope before approving a tool call. Granola
returns only notes available to the connected user in their active workspace; switch the active
workspace in Granola before querying a different one. Transcript and folder tools may require a
paid plan.

## Trigger a Workflow

Granola's **Meeting notes ready** event (`meeting.notes_ready`) starts a Workflow after Granola
generates the meeting's AI summary. opencompany checks for new summaries every five minutes; this
is not an instant notification when the call ends.

1. Open **Plugins → Granola** and install or update the plugin.
2. In **Events**, save a personal Granola API key. Create it in Granola's desktop app under
   **Settings → Connectors → API keys**, with access to the meetings you want to use.
3. Turn on **Meeting notes ready**. Events are off by default.
4. Open a Workflow, choose **On an event → Granola → Meeting notes ready**, and select your account.
5. Optionally choose a folder. It includes meetings in that folder and its subfolders; leaving it
   empty includes all meetings available to the API key.
6. Write the step instructions and activate the Workflow before finishing a new meeting.

The event uses the personal API-key connection in the plugin's **Events** section. MCP OAuth powers
the tools separately and does not authorize this polling connection. Saving the key does not turn
on an event or activate a Workflow, and no Wiki or Brain source is required.

Granola requires **Business or Enterprise API access** to create API keys. Enterprise administrators
may need to enable API key scopes for members. See [Granola API access](https://docs.granola.ai/introduction).

Each meeting starts a given Workflow at most once, including when a later poll sees an edited
summary. Events from before Workflow activation and notes last updated more than a day earlier
are excluded. The task receives the meeting title, time, attendees, note URL, and summary as context.
The event does not need to download the transcript, so a long transcript cannot block it.

For a first test, use a step such as:

```text
Use the meeting summary supplied by this event to list decisions, open questions, and action items.
Include an owner or due date only when the notes state one.
```

Wait until Granola has generated the summary, then allow one polling interval and check the
Workflow's runs. If your steps need more meeting content, connect the MCP account too and configure
its tool permissions for unattended use. The event toggle does not grant additional tool access.

If no run appears, check the API key's status and note access, the event toggle, the Workflow's
active status, and any folder filter. A rejected key appears as needing reconnection in **Events**.
Disabling the event or Workflow prevents pending deliveries from starting new tasks; an already
running task uses the ordinary task cancellation control.

Automatic provider-to-Wiki ingestion has been retired. Existing API-key connections can be reused
for events from the plugin page. Removing or reinstalling the plugin does not delete that separate
connection.

See [Granola's MCP guide](https://docs.granola.ai/help-center/sharing/integrations/mcp) for current
plan limits, workspace access controls, and provider troubleshooting.
