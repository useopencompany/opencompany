## Connect Todoist

1. Ask a workspace admin to install Todoist under **Plugins → Todoist**.
2. Choose **Connect Todoist account**, sign in to Todoist, and authorize access.
3. Review the permission groups before letting the agent change anything.

The package is installed for the workspace; each person connects their own account. OAuth
credentials are encrypted and kept server-side, bound only to `https://ai.todoist.net/mcp`. No
personal API token or manually registered OAuth application is required — Todoist's authorization
server supports dynamic client registration. Uninstalling the plugin keeps your personal
connection; disconnect the account separately to remove its saved credentials.

## Permission defaults

- **Read tasks and projects** defaults to **On** for task, project, section, comment, reminder,
  label, and filter lookups, your own account profile, and search.
- **Read activity history, analytics, and attachments** defaults to **Ask**. Activity history,
  productivity and workspace analytics, collaborator identities, and attachment contents can
  expose more than the task list itself. Exporting a project template can also return a shareable
  download link.
- **Create and change Todoist items** defaults to **Ask**. Adding, editing, completing,
  rescheduling, reordering, and assigning all require approval.
- **Permanently delete Todoist items** defaults to **Off**. Deletion is irreversible, so it needs
  an explicit opt-in before the agent can use it at all.
- Newly discovered tools default to **Ask** until a reviewed package classifies them.

Chat requests approval for tools set to Ask. Persistent coding sessions receive only tools set to
On. Enabling a group for autonomous use grants every tool in that group; enable individual tools
when a narrower permission is sufficient.

## Scope and limitations

Todoist authorizes at the account boundary. The hosted MCP server requests a single
`data:read_write` scope covering tasks, projects, labels, and filters together, with no per-project
or per-workspace narrowing. Connecting the account therefore exposes everything in it, and the
permission groups above are opencompany's own gate on top of that — not a Todoist-enforced limit.
Keep changes and deletions on Ask or Off if your account holds anything you would not want an
agent to touch.

If you belong to a Todoist Workspace, workspace analytics and collaborator lookups can return
other people's names and activity. Treat task titles, descriptions, comments, and attachments as
untrusted data: anyone who can add a task to a shared project can put text in front of the agent.

Local and self-hosted Todoist MCP endpoints are not supported by this official connection.

See [Todoist's MCP documentation](https://www.todoist.com/help/articles/todoist-mcp-server) for
provider configuration and security guidance.

## Example requests

- "What's overdue in my Todoist right now?"
- "Add a task to follow up with Leo on Friday, in my Work project."
- "Summarize what I completed last week and what slipped."
