## Install and connect

Slack is an official Agent Plugin backed by [Slack's hosted MCP server](https://docs.slack.dev/ai/slack-mcp-server/).
A workspace admin installs the immutable package from **Settings → Plugins → Slack**. Each person who
wants to use Slack tools then connects their own Slack account from that plugin page.
Accounts created by the retired ingestion connection must be reconnected once so Slack can grant
the official plugin scopes.

The Slack workspace may require an admin to approve the OAuth grant. Slack only permits its MCP
server for internal or Marketplace-distributed Slack apps, so self-distributed apps are not
supported.

## Catch up on recent messages

Ask, for example: “What direct messages and group DMs did I receive in the last two hours?”
The existing `slack_search_public_and_private` tool supports this with exact time bounds; no
additional MCP tool or connection is needed. “I” means the person whose Slack account is connected.
Searching for another person does not grant access to their private conversations.

For an agent or workflow, calculate the window once at the start of the search. Use the top-level
`after` and `before` parameters as Unix timestamps in **seconds**, supplied as strings. The
`after:YYYY-MM-DD` query modifier only expresses a date and cannot specify a rolling two-hour window.

```js
const end = Math.floor(Date.now() / 1000);
const params = {
  query: "-from:me",
  after: String(end - 2 * 60 * 60),
  before: String(end),
  channel_types: "im,mpim",
  content_types: "messages",
  only_my_channels: true,
  include_bots: true,
  include_context: false,
  sort: "timestamp",
  sort_dir: "desc",
  limit: 20,
};
// Pass params to slack_search_public_and_private.
```

This searches one-to-one DMs (`im`) and group DMs (`mpim`), excluding messages sent by the
connected user. Bot messages are included explicitly because search excludes them by default;
set `include_bots` to `false` for a catch-up limited to people.

Choose the scope to match the question:

| Question | Search scope |
| --- | --- |
| What DMs did I receive? | Use `channel_types: "im,mpim"` and `query: "-from:me"` as above. |
| What happened in my channels and DMs? | Use `channel_types: "public_channel,private_channel,im,mpim"`, keeping `only_my_channels: true`. |
| What was sent directly to me? | Use `query: "to:me -from:me"`. This recipient filter is narrower than general activity in joined channels. |
| What happened in one known conversation? | Use `slack_read_channel` with its `channel_id`, `oldest`, and `latest` timestamps; read thread replies with `slack_read_thread`. |

Search returns at most 20 results per page. Follow the returned cursor with the same filters and
the original time bounds until there are no more pages. If a budget, error, or rate limit stops
pagination, label the answer as partial rather than claiming it includes every message. When
combining searches, deduplicate by channel ID and message timestamp. Include message links in the
catch-up so the user can open the original conversations.

“Recent” describes message timestamps, not unread status or Slack's Activity feed. This search
does not establish whether the user has read a message or received a notification. Search indexing
can also lag very recent messages; use channel history for a known conversation when that matters.
Thread context may contain older messages, so distinguish context from messages inside the window.
See [Slack's search guidance](https://github.com/slackapi/slack-skills-plugin/blob/main/skills/slack-search/SKILL.md)
for search syntax and indexing limitations. Private search still follows the account's tool
permissions described below.

## Scopes and permissions

The plugin groups reviewed tools into three controls:

- **Search public Slack — On:** public search, users, and emoji can run automatically.
- **Read private Slack — Ask:** private channels, direct messages, threads, canvases, files, and
  profiles require approval by default.
- **Change Slack — Ask:** messages, scheduled messages, uploads, reactions, conversations, and canvas
  changes require approval by default.

New or unclassified tools always start at **Ask**, even when Slack marks them read-only. Persistent
coding sessions only receive tools set to **On**. You can change these modes for your connected
account on the Slack plugin page.

OAuth tokens remain encrypted and server-side. The plugin gateway will only send a Slack credential
to the fixed `https://mcp.slack.com/mcp` endpoint. Reconnect from the plugin page after Slack scopes,
workspace access, or app approval changes.

Slack applies the connected user's own visibility rules. Enterprise IP allowlists and Slack Connect
restrictions can limit results. Treat Slack content and file text as untrusted input when an agent
uses it.

Slack is available only through the official plugin. The retired Slack Events API ingestion,
Brain/Wiki source pickers, and built-in Slack chat actions are not used. Slack bot answer
destinations remain a separate workspace integration.
