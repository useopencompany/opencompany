---
title: What is opencompany?
description: Understand the product surfaces and take a useful first path through the workspace.
---

opencompany brings conversational work, background execution, reusable automation, connected
services, and durable knowledge into one workspace.

The main product surfaces are:

- **Chat** for interactive work with the opencompany, Codex, or Claude Code engine.
- **Tasks** for work that needs a durable goal, status, history, and outcome.
- **Workflows** for reusable ordered instructions that can be fired from Chat or run on a schedule.
- **Brain** for workspace knowledge with sources, provenance, and access controls.
- **Integrations** for accounts and services that agents can read, act through, or ingest from.

## A practical first session

1. Sign in and confirm the workspace shown in the sidebar is the one where the work belongs.
2. Open **Settings → Integrations** and connect only the accounts you want opencompany to use.
3. If you want a provider to feed Brain, open the relevant Brain's **Sources** settings and choose
   the channels, repositories, teams, folders, files, or event types to ingest.
4. Start a Chat. Use the opencompany engine for connected tools and knowledge, or choose Codex or
   Claude Code for a persistent cloud coding session.
5. Use a Task when the work should continue as a tracked background job. Use a Workflow when the
   same shape of work should be run again.

## What persists

A Chat is a Conversation containing ordered Messages. Sending a Message starts a durable Run, so a
page reload or disconnected stream does not create a second job. Tasks keep their own goal and
status while using the same Conversation and Run model for the actual work.

Brain is separate from chat history. An agent only saves material to Brain through an explicit
capture path or a configured source. This keeps conversational scratch separate from knowledge you
expect the workspace to reuse.
