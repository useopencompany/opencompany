## The whole thing in one screen

An `.agent` file has YAML frontmatter for configuration and a Markdown body for instructions.

```yaml
---
version: 2
title: "AMP code agent"
model: openai/gpt-5.4
tools:
  - id: amp
    type: coding_agent
    provider: amp
    repository: web-app
    prCapable: true
  - id: exa
    type: hosted_tool
integrations:
  github:
    repositories:
      - id: web-app
        fullName: opencompany/opencompany
        defaultBranch: main
triggers:
  - id: pr-work
    type: github.pull_request
    repository: web-app
    events: [opened, reopened, synchronize, ready_for_review]
    branches: [main]
    enabled: false
---

Use @amp for code changes in @opencompany/opencompany. Open draft PRs when the task is ready for review.
```

The header controls what the runtime can do. The body tells the model how to behave.

## Frontmatter

| Field | What it means |
| --- | --- |
| `version` | Current value: `2`. |
| `title` | Agent name shown in the app. |
| `model` | Model used by the main OpenCompany agent. |
| `tools` | Callable capabilities like Exa or AMP. |
| `integrations` | Connected resources, such as GitHub repositories. |
| `triggers` | Event entrypoints. PR triggers are saved but not active yet. |

Tools are callable runtime capabilities. Integrations are external resources or authority
boundaries. Platform provider credentials can power tools without becoming integrations in the
`.agent` file.

Supported models:

| ID | Good for |
| --- | --- |
| `openai/gpt-5.4-mini` | Default fast agent work. |
| `openai/gpt-5.4` | More complex reasoning. |
| `anthropic/claude-haiku-4.5` | Fast Claude workloads. |
| `anthropic/claude-sonnet-4.6` | Coding-heavy and careful work. |

## Tools

Tools are structured callable capabilities.

```yaml
tools:
  - id: exa
    type: hosted_tool
```

`exa` lets the agent search and fetch live web sources.

```yaml
tools:
  - id: amp
    type: coding_agent
    provider: amp
    repository: web-app
    prCapable: true
```

`amp` lets the main agent delegate code changes to Amp inside an E2B sandbox. AMP is a tool; the
repository value must match a GitHub repository listed under `integrations` because GitHub is the
connected resource AMP works against.

`prCapable: true` means the agent can create a generated branch and draft pull request when its
instructions call for it. It does not allow direct pushes to the default branch.

## Integrations

GitHub repositories live under `integrations.github.repositories`.

```yaml
integrations:
  github:
    repositories:
      - id: web-app
        fullName: opencompany/opencompany
        defaultBranch: main
```

The `id` is the short handle used by tools and triggers. The OpenCompany-managed workspace repo
that stores `.agent` files is separate from these GitHub work integration repositories.

AMP does not live under `integrations`. OpenCompany's platform AMP credential powers the AMP tool
outside the `.agent` file.

## Triggers

Pull request triggers can be saved now:

```yaml
triggers:
  - id: pr-work
    type: github.pull_request
    repository: web-app
    events: [opened, reopened, synchronize, ready_for_review]
    branches: [main]
    enabled: false
```

They are intentionally inactive in this release. Webhook execution will be added later.

## Body and mentions

The body is Markdown. Write the outcome, constraints, review policy, and preferred workflow here.

Rich mentions like `@amp`, `@exa`, or an explicit GitHub work repository mention such as
`@opencompany/opencompany` are the authored source for selected tools and integrations. The server
derives the structured frontmatter from these mention nodes on save, then downstream runtime code
reads the normalized frontmatter.

Use the Add Mention menu to insert supported tool and integration mentions. For AMP, mention both
`@amp` and the GitHub work repository it should use. Removing a supported mention from the body
removes its derived frontmatter config on the next save.

Model shortcuts are still recognized in the editor:

| Mention | Model |
| --- | --- |
| `@fast`, `@default` | `openai/gpt-5.4-mini` |
| `@deep` | `openai/gpt-5.4` |

## Validation

The parser tries to keep files loadable:

- Unknown models fall back to `openai/gpt-5.4-mini`.
- Unknown tools are dropped.
- Invalid GitHub repositories are dropped.
- AMP with a missing repository binding stays visible but cannot run until fixed.
- Triggers pointing at missing repositories are dropped.

## Builder mapping

The agent builder writes this same YAML:

- The model menu updates `model`.
- Add Mention tool selections derive `tools`.
- Add Mention integration selections derive `integrations.github.repositories`.
- The right sidebar configures the selected GitHub repository for AMP work.
- The AMP tool points at the selected repository when one is configured.
- The pull request trigger control writes a disabled trigger draft.
