title: Engineering notes workflow
description: How to maintain the embedded engineering notes while the standalone user docs are prepared.
---

## Source files

User- and API-facing documentation lives in the standalone Fumadocs app under
`apps/docs/content/docs`. The files in `apps/web/content/docs` are retained engineering notes served
by the product until the owner chooses the standalone docs hosting and domain cutover.

Each page is an MDX file with frontmatter:

```mdx
---
title: Page title
description: One sentence summary.
---
```

Update `apps/web/content/docs/meta.json` when adding, removing, or reordering pages.

## When to update docs

Update the standalone user docs when a change affects product behavior. Update these embedded notes
only when a change affects the engineering material still rendered by the product, including:

- Chat or task flow.
- Runner behavior for opencompany tasks.
- Tool availability, model selection, or task planning.
- Setup, local development, or operational debugging.

Small internal refactors do not need docs unless they invalidate an existing page.

## Verification

For the standalone site, run:

```bash
bun --filter @opencompany/docs lint
bun --filter @opencompany/docs typecheck
bun --filter @opencompany/docs build
```

For an embedded-note change that touches the existing web MDX routing or rendering, run:

```bash
bun --filter @opencompany/web typecheck
bun --filter @opencompany/web build
```

For route or rendering changes, open the affected app and click at least one nested docs page.
