## What Brain is

Brain is opencompany's durable workspace knowledge store: Markdown knowledge pages, immutable
evidence, file-backed documents, provenance, and a lightweight graph of typed relations and wiki
links. Postgres is the source of truth.

The current ownership boundary is:

- `packages/brain` owns document parsing, schemas, validation, retrieval helpers, the
  filesystem CLI, and the pointer/copy rule.
- `packages/agent` owns shared Brain reads, capture behavior, MCP tools, and asset behavior.
- `packages/db` owns tables, repository queries, fixed read projections, and temporary filesystem
  materialization.
- `apps/api` owns authenticated Brain commands, assets, sources, MCP, authorization, and API read
  models.
- `apps/runner` owns durable ingestion/import, provider polling, Google Drive sync, and agentic
  curation.
- `apps/web` renders Brain and calls typed `/v1` commands or named read models. It does not import
  Brain repositories or write tables.

## Document model

A Brain document has a stable slug (`brain_id`) within one Brain (`brain_ref`), a folder, kind,
entity type, status, compiled truth, and an append-only evidence timeline.

- `kind` is `page` or `evidence`. Evidence must live under `evidence/`; pages must live outside it.
- `type` is one of `person`, `company`, `project`, `meeting`, `concept`, `source`, `analysis`, or
  `note`.
- `status` is `draft`, `active`, `archived`, or `merged`. Active pages require cited provenance.
- `relations` and typed `[[page:...]]`, `[[evidence:...]]`, and `[[source:...]]` links produce the
  durable graph and citations.
- `format` may be Markdown or a supported file type such as PDF, DOCX, XLSX, CSV, JSON, text, or
  image. Private bytes stay behind authenticated API routes while the row keeps searchable metadata
  and extracted text when supported.

The detailed schema reference is in `docs/brain/data-model.md`; code-level truth lives in
`packages/brain/src/schema.ts` and `packages/db/src/product-schema.ts`.

## Pointer/copy rule

Brain writers prefer canonical pointers over stale copies. Claims cite a provider source ref.
Ephemeral or unfetchable content may be snapshotted under `evidence/`; live systems such as issue
trackers or Drive remain the canonical home and are represented by a pointer plus synthesized facts.
The shared prompt contract lives in `packages/brain/src/pointer-copy.ts`.

## Commands and reads

The Brain UI uses authenticated `/v1/brains/*` commands for document, folder, source, membership,
import, and asset changes. Updates use optimistic content hashes and creation uses durable
idempotency. Fixed `brain-*-v1` read models keep authorized folders, documents, timelines, graph
edges, source state, and ingestion activity current after hydration.

Chat and MCP use the shared read surface in `packages/agent/src/brain-surface.ts` and
`brain-cli.ts`. Search, list, point reads, and timelines execute against indexed Postgres queries in
`packages/db/src/brain-read.ts`; they do not materialize the whole Brain. Chat and MCP expose
capture-to-curation rather than arbitrary mutation CLI commands.

The API hosts MCP at `/mcp`; the web `/mcp` URL is only a continuity relay. Each MCP call resolves
the verified user, selects an accessible Brain, and rechecks membership. `save_to_brain` preserves
the workspace-admin write boundary.

## Capture and ingestion

`save_to_brain` creates a visible draft in `inbox/`, records a normalized source item, and commits a
durable curation job. opencompany Chat invokes this through the runner host-tool boundary; API-hosted
MCP uses the same shared capture behavior. Ref-only Slack, Gmail, and Linear captures can hydrate the
provider source in the runner before curation.

Provider ingress and polling follow the same durable rail:

```text
verified API ingress, API command, or runner poller
  -> goat.brain_source_items
  -> goat.brain_ingest_jobs
  -> runner fenced claim
  -> validated handler and curation
  -> committed Brain rows and terminal job state
```

Notifications and authenticated wake routes reduce latency only. The committed job, lease, and
polling loop own admission and recovery. Agentic handlers materialize one authorized Brain into a
temporary root so they can read their own writes through the allowlisted CLI, then sync validated
changes back at job completion.

Registered source families include meeting providers, Chat/MCP capture, uploaded assets, Google
Drive documents, Slack/Gmail/Linear pointers, and provider activity from GitHub, HubSpot, Attio, and
other current integrations. The handler registry in
`apps/runner/src/brain-ingest-worker.ts` is the executable source of truth.

## Access and validation

Every Brain query and mutation is pinned to one `brain_ref`. Workspace-visible Brains follow
workspace membership; restricted Brains additionally require a Brain membership row. API commands,
read models, MCP, runner jobs, and asset routes each enforce that boundary rather than trusting a
client-supplied workspace.

`validateBrainDocument` enforces identifiers, folder/kind alignment, statuses, timestamps,
links, and active-page provenance on write. `opencompany-brain doctor` performs corpus integrity checks for
broken links, citations, aliases, relations, and weak provenance.
