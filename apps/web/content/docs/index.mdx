## What opencompany is

opencompany is a place to build and run the AI agents your company uses every day — for research, ops, sales, support, anything you'd normally hand to a teammate or a script.

The thing that makes it different is how agents are stored. Every agent is a **plain text file** in a private GitHub repo that belongs to your workspace. No proprietary database, no closed format. If you can read Markdown, you can read your agents.

This means:

- You can see exactly what an agent does — its instructions are right there in the file.
- Every change is versioned in Git. You get history, diffs, and pull requests for free.
- You can edit in the opencompany editor, in GitHub, or in your favorite code editor. They all read the same file.

## The core ideas

### Workspace

A workspace is your company's space in opencompany. It has its own members, its own private GitHub repo, and its own set of agents. Most companies will only ever need one.

### Agent

An agent is one job your company wants done. "Research investors." "Triage incoming bugs." "Draft replies to support tickets." Each agent is a single `.agent` file with a title, instructions, the AI model that runs it, and the tools it can use.

### Instructions

The body of an agent file is just Markdown — the same plain text you'd use to write a doc. You describe the outcome you want, the constraints that matter, and how the agent should behave. The AI model reads it the same way a new teammate would read an SOP.

### Mentions

Inside the instructions, you can write `@exa` to give the agent web research, or `@deep` to run it on a more capable model. These `@` mentions are the only way to wire up models and tools — the editor reads them out of the instructions automatically, so you never have to keep two places in sync.

### Sync

Everything you save in the opencompany editor is committed to your workspace's GitHub repo. Edits in either place flow through. Your agents are yours, in Git, forever.

## A tiny example

Here's what an agent file looks like end to end:

```yaml
---
title: "Investor research"
model: openai/gpt-5.4
tools:
  - exa
---

Find recent fund announcements with @exa. Write a one-paragraph brief for
each fund covering thesis, check size, and a recent investment. Use @deep
when summarizing — accuracy matters more than speed.
```

That's the whole thing. A header that says who this agent is and what it can use, and a body of instructions in plain English. To change the model, change `@deep`. To remove web research, remove `@exa`. The file always reflects exactly what the agent does.

## What you can do today

- **Create agents** in the editor at `/agents`. Give them a title, write instructions, and add `@` mentions for the model and tools you want.
- **Edit agents** any time. Saves are instant — the GitHub commit happens in the background a few seconds later.
- **Read the file format** in detail on the next page if you want to understand every option, or if you're planning to author agents directly in your editor.
